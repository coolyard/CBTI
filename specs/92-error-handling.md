# 92 · 错误处理规范

> 原则：**fail-fast 给开发者，温柔兜底给用户，禁止静默 catch。**

## 1. 错误分类与处置

| 类别 | 示例 | 处置 |
|------|------|------|
| 数据完整性错误 `DataIntegrityError` | 题库不过 Zod、模式串非法、候选池为空 | **启动即抛**（`src/data/index.ts` 顶层校验），开发期立刻暴露；页面不兜底 |
| 流程错误 `IncompleteAnswersError` | 未答满 15 题就 computeResult | core 抛出；store 层保证不发生，发生即视为 bug |
| 能力错误 | canvas 获取失败、图片加载失败、相册授权被拒 | UI 降级 + 用户可理解的提示 + 可重试入口（见 §2） |
| 平台错误 | 剪贴板不可用、分享接口失败 | toast 提示 + 提供替代路径（如手动长按保存） |

## 2. 用户侧兜底标准

| 场景 | 兜底 |
|------|------|
| 雷达图 canvas 失败 | 降级为文字列表（specs/55 §7） |
| 立绘加载失败 | 首字符占位图，不阻断海报导出 |
| 海报导出失败 | toast「海报生成失败，再试一次」+ 保留重试按钮 |
| 相册授权被拒 | 引导弹窗「去设置开启相册权限」，二次点击直达设置 |
| 加载页 result 超时（5s） | 强制跳结果页；结果页字段缺失走占位文案 |

## 3. 日志

- 统一 `src/utils/logger.ts`：`log.info / log.warn / log.error`，携带 `[CBTI]` 前缀与场景 tag。
- 用户可见提示一律用 specs/60 的语气（如「海报生成失败，再试一次嘛」），禁止弹技术错误原文。
- 禁止空 `catch {}`；catch 必须至少 `log.error` 且有明确兜底行为。
