# 90 · 测试规范

> 目标：核心逻辑 100% 可靠，UI 人工可验。MVP 不追求 UI 自动化测试。

## 1. 测试分层

| 层 | 工具 | 范围 | 覆盖率要求 |
|----|------|------|-----------|
| 纯逻辑单测 | Vitest | `src/core/**`（计分/匹配/彩蛋/engine） | **分支覆盖 100%** |
| 数据校验 | Vitest（Zod） | `src/data/**` 两套题库 + 角色库 | 全量校验，见 specs/30 §7-11 |
| 组件/页面 | 人工 QA | 按各页面 spec 的验收清单逐项打勾 | 每个页面 spec 的 checklist 全过 |
| 端到端冒烟 | 人工 | §3 设备矩阵跑完整流程 | 发布前必做 |

## 2. 单测编写规则

- 测试文件与被测文件同目录：`src/core/__tests__/*.test.ts`。
- 用例必须覆盖 specs/30 §7 列出的 11 条，编号与 spec 对应（测试名里带 `#1`…`#11`）。
- 测试数据：集成用例使用**真实题库/角色库**（顺带回归数据）；边界用例用最小构造数据。
- 禁止 snapshot 一把梭；断言到具体值。

## 3. 设备/环境矩阵（冒烟）

| 环境 | 用例 |
|------|------|
| Chrome 移动视图（iPhone 尺寸） | 完整流程 + 海报下载 |
| 微信开发者工具（iPhone 机型） | 完整流程 + 海报保存 + 分享卡片 |
| 真机微信（至少 1 iOS 或 1 Android） | 完整流程 + 性能体感 |

## 4. 通过门槛（进 CI）

`npm run lint && npm run typecheck && npm run test` 全绿才允许合并/交付。
